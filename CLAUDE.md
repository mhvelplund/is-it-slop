This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

"Is It Slop?" is a cross-browser (Chrome + Firefox) WebExtension, built with
[WXT](https://wxt.dev). A user selects text on any page, right-clicks "Is it
slop?", and gets an AI judgment of whether the text is AI-generated. The user
brings their own Anthropic or OpenAI API key; there is no backend — the
extension calls the provider's API directly from the browser.

Design spec: `docs/superpowers/specs/2026-08-11-is-it-slop-design.md`.

## Commands

```bash
npm run dev            # wxt dev, Chrome
npm run dev:firefox    # wxt dev, Firefox
npm run build          # production build -> .output/chrome-mv3/
npm run build:firefox  # production build -> .output/firefox-mv3/ (or mv2, depending on WXT version)
npm run zip / zip:firefox
npm run compile        # tsc --noEmit
npm test               # vitest run (whole suite)
```

Run a single test file: `npx vitest run lib/path/to/file.test.ts`
Run a single test by name: `npx vitest run lib/path/to/file.test.ts -t "test name"`

Always run `npm run compile` in addition to `npm test` — most `lib/` bugs
surface in the test suite, but real API-shape mismatches against the
Anthropic/OpenAI/WXT SDKs only show up as `tsc` errors (see Gotchas below).

## Architecture

Two layers, deliberately separated:

- **`lib/`** — plain, framework-free TypeScript. All business logic:
  storage, criteria caching, provider clients, analysis orchestration,
  verdict rendering. Every non-trivial function here takes its dependencies
  as parameters (see `lib/run-analysis.ts`'s `AnalysisDeps`,
  `lib/validate-and-save-key.ts`'s injected `validateKey`) so it's testable
  with fakes instead of real network/storage. This is why almost every file
  in `lib/` has a co-located `.test.ts`.
- **`entrypoints/`** — WXT's browser-API glue: `background.ts` (service
  worker), `content/` (the floating verdict card), `options/` (the React
  settings page). These import from `lib/` but contain no business logic of
  their own, and are not unit-tested — WXT auto-imports `browser`,
  `defineBackground`, `defineContentScript` as globals here (no explicit
  import needed).

### Data flow

1. User selects text, right-clicks "Is it slop?" — the menu item
   (`lib/context-menu-sync.ts` decides its enabled state) is disabled
   whenever the active provider has no `valid` key.
2. `entrypoints/background.ts`'s `contextMenus.onClicked` handler sends a
   `SLOP_LOADING` message to the tab, then calls
   `lib/run-analysis.ts#runAnalysis` (truncates selection to 8,000 chars,
   loads the criteria text, calls the active provider), then sends
   `SLOP_RESULT` or `SLOP_ERROR` to the same tab.
3. `entrypoints/content/index.ts` renders the result in a Shadow-DOM card
   (`createShadowRootUi`), positioned via `window.getSelection()`.

### Provider abstraction

`lib/providers/types.ts` defines `ProviderClient` (`validateKey`,
`evaluateText`); `lib/providers/anthropic.ts` and `lib/providers/openai.ts`
implement it; `lib/providers/index.ts` is the `Provider -> ProviderClient`
registry. Both providers:
- Construct their SDK client with `dangerouslyAllowBrowser: true` (this is
  a deliberate BYOK choice, not an oversight — see the comment in
  `anthropic.ts`).
- Validate a key via `client.models.list()` — cheap, no token cost.
- Request structured output against `lib/providers/prompt.ts`'s
  `slopVerdictSchema` (Zod), so both providers return the same
  `SlopVerdict` shape regardless of SDK.
- Current models: Anthropic `claude-haiku-4-5`, OpenAI `gpt-5.6-luna`.

### Criteria caching

`lib/criteria/get-criteria.ts` implements a 24h cache over the Wikipedia
"Signs of AI writing" page (fetched via the MediaWiki `action=query&prop=extracts`
API in `fetch-wikipedia-extract.ts`). Fallback chain on fetch failure: stale
cache -> bundled snapshot (`lib/criteria/fallback-snapshot.txt`, imported via
Vite's `?raw` import). The snapshot is regenerated by running
`npx tsx scripts/fetch-criteria-snapshot.ts` (a real network call) — it is
not meant to be hand-edited.

### Storage

`lib/storage.ts` wraps `wxt/utils/storage`'s `storage.defineItem` for two
keys: `local:settings` (`StoredSettings` — active provider, both providers'
API keys, both providers' validity) and `local:criteriaCache`. Everything is
`browser.storage.local` — never `sync` — so API keys never leave the device.

## Gotchas (verified against installed package versions, not guessed)

These import paths and API shapes look plausible from the SDKs' own docs
but don't match what's actually installed. Verify against `node_modules`
before assuming a similar-looking path/signature is correct elsewhere:

- WXT's storage helper is at `wxt/utils/storage`, **not** `wxt/storage`.
- WXT's Shadow DOM UI helper is at
  `wxt/utils/content-script-ui/shadow-root`, **not** `wxt/client`.
- `tsconfig.json`'s `extends` must be `"./.wxt/tsconfig.json"` (leading
  `./`) — without it, `tsc` resolves the path via Node package resolution
  instead of as a relative file and fails with `TS6053`.
- Anthropic's `zodOutputFormat(schema)` takes **one** argument. OpenAI's
  `zodTextFormat(schema, name)` takes **two**. Don't copy one signature to
  the other provider file.
- `scripts/fetch-criteria-snapshot.ts` needs `@types/node` (Node builtins
  aren't covered by the rest of the project's browser-oriented tsconfig).

## Testing conventions

- Storage/browser-API-dependent tests use `fakeBrowser` from
  `wxt/testing/fake-browser`, reset in `beforeEach`.
- SDK-dependent provider tests (`lib/providers/anthropic.test.ts`,
  `openai.test.ts`) fully mock `@anthropic-ai/sdk` / `openai` and their
  `helpers/zod` modules — no real network calls in the test suite.
- `vitest.config.ts` uses `WxtVitest()`, which supplies the `@/` path alias
  and browser polyfills for tests, matching `wxt.config.ts`'s runtime alias.
